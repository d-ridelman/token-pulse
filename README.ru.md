# Token Pulse

[English README](README.md)

Token Pulse — локальное приложение на Electron для просмотра **скорости выходных токенов завершённых ответов Codex**. Оно показывает недавние сессии, выбранную модель и уровень рассуждения, спидометр и таймер текущего хода. Интерфейс доступен на русском и английском; по умолчанию выбран русский.

## Скачать и запустить

В [последнем релизе](https://github.com/d-ridelman/token-pulse/releases/latest) есть переносимый EXE для Windows x64. Для его запуска не нужны установщик и Node.js. Сейчас EXE не подписан цифровой подписью.

Для запуска из исходников на Windows, macOS или Linux нужны Node.js и npm:

```sh
npm ci
npm start
```

В Windows `start.cmd` также запускает локально установленный Electron. `npm test` проверяет модуль чтения журналов. `npm run build:portable` собирает переносимый EXE в папке `release/` на Windows.

## Только один проект

По умолчанию приложение читает локальные сессии Codex из `CODEX_HOME/sessions`, а если переменная `CODEX_HOME` не задана — из `~/.codex/sessions`. Чтобы видеть только сессии, запущенные в конкретной папке и её вложенных каталогах, укажите абсолютный путь в `TOKEN_PULSE_PROJECT_DIR`. Язык при запуске можно задать через `TOKEN_PULSE_LANG=en` или `ru`:

```powershell
$env:TOKEN_PULSE_PROJECT_DIR = 'C:\work\my-project'
$env:TOKEN_PULSE_LANG = 'ru'
npm start
```

Фильтр использует рабочую папку из метаданных каждой сессии. Карточки других проектов не попадают в выбранный вид.

## Что означает скорость

Основной источник — событие Codex `token_usage_record`. Приложение делит выходные токены **завершённого ответа модели** на время от ближайшего доступного события перед запросом (начала хода или завершения последнего инструмента) до записи о расходе. Для старых журналов используется разница накопленных счётчиков `token_count`. Метод указан в карточке.

Выходной счётчик включает токены рассуждения и другой невидимый вывод. Во время замера может входить задержка запроса. Локальный журнал не сообщает точное время первого токена и не содержит потока по одному токену, поэтому это **эффективная скорость завершённого ответа**, а не мгновенная скорость генерации. Сырые токены в секунду разных токенизаторов не равнозначны одинаковому объёму текста.

Известные активные файлы проверяются каждые 100 мс; когда возможно, используются и уведомления файловой системы. Число меняется только после новой записи о расходе Codex. Замер считается свежим 75 секунд, карточка остаётся видимой 20 минут.

Спидометр показывает сумму свежих замеров или выбранную сессию. Стрелка плавно приходит к новому значению, а цифровое число сразу показывает записанный результат. Промежуточные положения стрелки — анимация, не новые измерения. Шкала: 0–240 ток/с для суммы и 0–120 ток/с для одной сессии; точное число видно и выше шкалы.

Во время активного хода отдельный индикатор показывает прошедшее время, тип последнего наблюдаемого события Codex и количество выбранных сигналов активности. Таймер движется между замерами скорости. Эти сигналы **не оценивают ещё не записанные токены**. Метка модели берётся из последних `turn_context.model` и `effort`; возможная переадресация запроса на сервере отдельно не проверяется.

## Публикация результатов и приватность

Кнопка **«Скопировать результат»** создаёт короткую сводку с моделью, числом выходных токенов, длительностью, скоростью и методом замера. Она не включает переписку, путь проекта, ID сессии и счётчики ввода. Автоматической публикации нет.

Приложение читает журналы локально и не подключается к аккаунту или телеметрии. Обычные веб-чаты ChatGPT в этот локальный источник не входят. Для публикации замера не загружайте сырые журналы Codex: используйте скопированную сводку или собственный скриншот.
